최장 멜로디 검색

문제

원곡 데이터와 입력 멜로디 하나가 주어짐. 입력과 가장 길게 연속으로 일치하는 구간의 길이 L, 그리고 길이 L로 일치하는 곡을 모두 구함 (최장 공통 부분 문자열).

키나 빠르기가 달라도 같은 멜로디로 판정. 그래서 음을 그대로 비교하지 않고, 칸마다 앞 칸과의 변화를 번호로 바꿔 저장한 뒤 번호끼리 비교. 원래 값은 바꾼 뒤 버림. 쉼도 한 칸.

변화 번호로 저장하는 방법

입력

원곡 파일은 블록의 반복. 블록 = 곡명 한 줄, 항목 수 n 한 줄, 다음 n줄에 음 높이 p와 길이 d.

사용자 입력은 항목 수 r 한 줄, 다음 r줄에 p d. p = -1이면 쉼.

블록끼리는 이어 붙이지 않음. 곡명이 같은 블록은 같은 곡.

출력

첫째 줄에 최대 일치 길이: L, 둘째 줄에 일치한 곡 (k곡), 다음 k줄에 길이 L로 일치하는 곡명을 중복 없이 사전 순으로 출력. 실행 시간 줄은 생략.

제한

  • 1 ≤ r ≤ 32
  • p = -1 또는 0 ≤ p ≤ 127 (MIDI 음 높이)
  • d는 양의 정수. 최댓값 4,294,967,557로 32비트 범위 초과, 64비트 정수 필요
  • 블록 길이 n ≤ 7,425

데이터

  • 출처: Lakh MIDI Dataset v0.1의 Clean MIDI 부분집합 (Colin Raffel, CC BY 4.0). MIDI 파일 17,256개.
  • 추출: 타악기와 음이 겹치는 구간을 빼고, 실제 음이 8개 이상 이어지는 단선율 구간만 블록으로 저장. 주선율을 따로 고르지는 않아 다른 악기의 단선율도 포함.
  • 규모: 파일 16,472개에서 블록 310,265개, 항목 30,477,226개 (음 16,795,768개, 쉼 13,681,458개). 같은 곡이 여러 블록으로 나뉨.
  • 값: 음 높이는 MIDI 번호, 길이는 원본 tick 그대로. 옮기거나 약분하지 않음.
  • 실험: 블록 순서를 섞은 뒤 앞에서부터 1천~100만 항목을 사용. 입력은 유형마다 50개, 16칸. 수록곡은 데이터 속 곡에서 그대로 자른 구간, 변형은 수록곡 구간을 키 변경·길이 2배·가운데 음 하나 변경, 미수록곡은 데이터에 없는 곡에서 자른 구간.
