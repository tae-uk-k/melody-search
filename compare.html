최장 멜로디 검색

문제 정의순차 배열정렬 배열체이닝 해시비교결과표
결론메모리 맹점어떤 걸 고를까Python이 느린 이유

세 방식 비교

결과표의 실측값(C++, 100만 항목)으로 정리한 결론과 선택 기준. 데이터 크기별 그래프와 전체 숫자는 결과표에 있음.

결론: 가장 빠른 방식은 입력에 따라 다르고, 균형은 정렬 배열

    해시의 치명적 맹점: 메모리

    정렬 배열: 시작 위치 하나에 숫자 하나

    조각 내용은 복사하지 않고 시작 위치 번호(4바이트)만 저장. 100만 항목이면 약 4MB.

    체이닝 해시: 시작 위치 하나에 조각 최대 32개

    입력과 몇 칸 일치할지 몰라 길이 1~32 표를 모두 만들고, 항목마다 해시값과 시작 위치(합 8바이트)를 저장. 같은 위치가 길이별로 최대 32번 들어가 100만 항목이면 약 327MB.

    전체 데이터(3,048만 항목)를 올리면

    • 100만 항목 측정값을 전체 데이터 크기로 비례 계산한 값.
    • 해시 색인만 약 10GB라 실험 PC 메모리(3.9GB)에 올릴 수 없음. 그래서 실험은 100만 항목까지.
    • 보완책: 검사할 길이의 조각만 그때그때 저장. 메모리는 1/32 수준이 되지만 검색마다 색인을 다시 만들어야 해서 검색이 느려짐.
