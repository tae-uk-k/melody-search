데이터 크기별 검색 시간

순차 배열정렬 배열체이닝 해시세로축은 10배씩 커지는 로그 눈금

DB에 있는 곡 (수록곡)

  • 데이터가 1,000배 늘 때 순차 배열만 그만큼 느려짐 (C++ 964배, Python 1,111배). 데이터가 클수록 색인이 필요.
  • 정렬 배열·해시는 100만 항목에서도 거의 그대로. C++는 정렬 배열이 가장 빠르고(0.54µs), Python은 둘이 비슷(약 30µs).

DB에 없는 곡 (미수록곡)

  • 정렬 배열·해시는 1천~5천 항목에서 오히려 느리고 1만 항목에서 가장 빠름. 작은 데이터는 짧게 겹치는 후보가 많아 확인할 곡이 많음.
  • 해시가 정렬 배열보다 조금 빠름. C++는 2천 항목까지 순차 배열이 가장 빠름, 데이터가 작으면 색인의 이득이 없음.

입력 유형별 검색 시간 (100만 항목)

순차 배열정렬 배열체이닝 해시C++Python로그 눈금

  • DB에 있는 곡은 C++에서 정렬 배열이 가장 빠르고, 변형·없는 곡은 C++·Python 모두 해시가 빠름. 입력 종류에 따라 더 빠른 쪽이 바뀜.
  • 없는 곡이 가장 느림 (C++ 정렬 배열 39.5µs, 해시 28.5µs). Python은 C++보다 순차 약 240배, 정렬 16~61배, 해시 9~38배 느림.

구축 비용 (100만 항목)

정렬 배열체이닝 해시C++Python로그 눈금

  • 해시는 정렬 배열보다 구축이 오래 걸림 (C++ 6.3배, Python 1.3배). 순차 배열은 구축 없음.
  • 해시가 구축에 더 쓴 1.2초(C++)를 검색으로 되찾으려면 없는 곡 기준 약 11만 번 검색 필요. 검색이 적으면 정렬 배열이 유리.

메모리 사용량 (100만 항목)

원곡 데이터정렬 배열 색인체이닝 해시 색인C++Python로그 눈금 · 원곡 데이터는 프로세스 메모리(RSS), 색인은 C++ 힙·Python getsizeof

  • 원곡 데이터·정렬 배열은 C++가 vector<int>(값만 4바이트), Python이 list(칸마다 포인터 8바이트 + int 객체)를 써서 Python이 3~9배 크고, 해시는 Python도 array("i")를 써서 C++와 같음.
