데이터 크기별 검색 시간

순차 배열정렬 배열체이닝 해시세로축은 10배씩 커지는 로그 눈금(점선은 2배·5배), 그래프마다 눈금 범위 다름

DB에 있는 곡 (수록곡)

  • 데이터가 1,000배 늘 때 순차 배열만 그만큼 느려짐 (C++ 964배, Python 1,111배). 데이터가 클수록 색인이 필요.
  • 정렬 배열·해시는 100만 항목에서도 거의 그대로. C++는 정렬 배열이 가장 빠르고(0.54µs), Python은 둘이 비슷(약 30µs).

DB에 없는 곡 (미수록곡)

  • 정렬 배열·해시는 1천~5천 항목에서 오히려 느리고 1만 항목에서 가장 빠름.
  • 데이터가 적으면 가장 길게 겹치는 길이가 짧아(1천 항목 평균 1.9칸) 그 길이로 겹치는 조각이 질의 하나에 약 2,100쌍이나 돼 모두 확인하느라 느림. 1만 항목부터는 최장 길이가 길어져(2.7칸 이상) 겹치는 조각이 50~300쌍으로 줄어듦.
  • 해시가 정렬 배열보다 조금 빠름. C++는 2천 항목까지 순차 배열이 가장 빠름, 데이터가 작으면 색인의 이득이 없음.

이론(빅O)과 실측 비교 (DB에 있는 곡)

순차 배열 O(N)정렬 배열 O(log N)체이닝 해시 O(1)이론 그래프는 일반 눈금으로 모양만 표시 · 실측 그래프 세로축은 1천 항목일 때 검색 시간의 몇 배 (로그 눈금), 점선은 이론

  • 이론: 데이터가 1,000배 늘면 순차 배열 O(N)은 1,000배, 정렬 배열 O(log N)은 2배(log₂100만 ÷ log₂1천 = 20 ÷ 10), 해시 O(1)은 그대로.
  • 실측: 순차 배열 C++ 964배·Python 1,111배, 정렬 배열 C++ 2.0배·Python 1.6배, 해시 C++ 1.1배·Python 1.0배. 세 방식 모두 이론과 거의 같게 늘어남.
  • 이론상 O(1)인 해시가 O(log N)인 정렬 배열보다 빨라야 하지만 C++ 수록곡은 정렬 배열이 더 빠름(0.54µs 대 0.83µs). 해시는 검색 전에 입력 조각의 해시값을 길이마다 모두 계산(16칸이면 136번)하지만, 정렬 배열은 입력 전체가 일치하면 이진 탐색 한 번(약 20번 비교)으로 끝나기 때문.
  • 중간에 오르내리는 것은 데이터 크기마다 질의 50개가 달라 일치 길이·일치 곡 수가 달라지기 때문. DB에 없는 곡은 위 설명처럼 작은 데이터에서 더 느려 이론과 다르게 움직임.

입력 유형별 검색 시간 (100만 항목)

순차 배열정렬 배열체이닝 해시막대마다 아래에 언어 표시 (진한 막대 C++, 옅은 막대 Python) · 로그 눈금

  • DB에 있는 곡은 C++에서 정렬 배열이 가장 빠르고, 변형·없는 곡은 C++·Python 모두 해시가 빠름. 입력 종류에 따라 더 빠른 쪽이 바뀜.
  • 없는 곡이 가장 느림 (C++ 정렬 배열 39.5µs, 해시 28.5µs). Python은 C++보다 순차 약 240배, 정렬 16~61배, 해시 9~38배 느림.

구축 비용 (100만 항목)

막대마다 아래에 언어 표시 (진한 막대 C++, 옅은 막대 Python) · 로그 눈금

  • 해시는 정렬 배열보다 구축이 오래 걸림 (C++ 6.3배, Python 1.3배). 순차 배열은 구축 없음.
  • 해시가 구축에 더 쓴 1.2초(C++)를 검색으로 되찾으려면 없는 곡 기준 약 11만 번 검색 필요. 검색이 적으면 정렬 배열이 유리.

메모리 사용량 (100만 항목)

막대마다 아래에 언어 표시 (진한 막대 C++, 옅은 막대 Python) · 로그 눈금 · 원곡 데이터는 프로세스 메모리(RSS), 색인은 C++ 힙·Python getsizeof

  • 원곡 데이터·정렬 배열은 C++가 vector<int>(값만 4바이트), Python이 list(칸마다 포인터 8바이트 + int 객체)를 써서 Python이 3~9배 크고, 해시는 Python도 array("i")를 써서 C++와 같음.
